# 投资 X Buddy — Evidence-first 对话式投研工作台

> 同花顺 2027 校招 AI 产品经理（AIME 金融智能 Agent 方向）笔试题13 作品。
> 用户给出研究目标 → 澄清范围 → 自动生成问题树 → 调用金融工具逐条取数**先落证据卡** → 产出**句句可溯源**的四分区报告 → 对话式修订（版本 diff 可回滚）→ 候选记忆经确认沉淀。
> 设计原则：**证据是主资产、问题树是规划、报告是视图、对话是遥控器**。

## 〇、产品选择（选题与技术栈）

- **选题**：三道题中选「题目13 投资 X Buddy」——其交付要求（工具注册/计划执行/上下文压缩/记忆/检查点/审批/停止规则/成本可观测/失败降级）与目标岗位 JD（金融智能 Agent 的规划、工具调用、记忆、反思机制）直接对应，能在 24h 内完整自证 Agent Harness 全链路。
- **产品形态**：证据优先（Evidence-first）的三区对话式投研工作台，而非"一键生成报告"黑盒——直接回应 JD"拒绝 Demo 式浅层 AI"，并把"结论可回溯"从口号变成结构（证据卡 + [E?] 行内引用 + provenance）。
- **技术栈**：Node.js + Express + SQLite（better-sqlite3，单文件零外部依赖，可单端口发布）+ 原生前端（无构建链，103 项测试用 Node 内置 test 即可跑）；LLM 走 OpenAI 兼容接口（小米 mimo）；金融数据走扶摇 REST API（`server/fuyao.js` 适配层，mock/fuyao 双数据源可切换）。

## 一、启动方式

```bash
npm install
cp .env.example .env   # 填入 LLM key（OpenAI 兼容接口）
npm start              # http://localhost:3210
npm test               # 自动化测试（103 项，无需 key；集成用例需服务已启动）
node tests/fuyao-smoke.mjs  # 扶摇真实数据源冒烟（需 FUYAO_API_KEY，无 key 自动跳过）
node tests/e2e-smoke.mjs   # 真实模式端到端冒烟（需 LLM key，约 3~6 分钟）
```

无 key 或无网络环境：新建研究时选「演示模式（轨迹重放）」，主链路零配置完整可跑。

## 二、环境变量（.env，不入仓库）

| 变量 | 说明 |
|---|---|
| `LLM_BASE_URL` | OpenAI 兼容接口地址 |
| `LLM_API_KEY` | LLM key（仅本地 .env，仓库只含 .env.example） |
| `LLM_MODEL_PLANNER` | 规划/叙事模型（默认 `mimo-v2.6-pro`，**注意模型名需全小写**） |
| `LLM_MODEL_LIGHT` | 轻量模型（问答/记忆提炼，默认 `mimo-v2.6-flash`） |
| `PORT` | 服务端口，默认 3210 |
| `DATA_PROVIDER` | `mock`（构造数据，默认）/ `fuyao`（扶摇真实数据，已接入）/ `ifind`（接口留位） |
| `FUYAO_API_KEY` | 扶摇（同花顺金融数据 API）密钥，仅本地 .env；`DATA_PROVIDER=fuyao` 时生效 |
| `FUYAO_BASE_URL` | 扶摇 API 地址，默认 `https://fuyao.aicubes.cn` |
| `FUYAO_FALLBACK_MOCK` | 设 `1` 时，仅 network/timeout/2001/5xx 失败允许回退 mock（显式标注）；默认关闭=一律诚实缺失 |

真实模式也支持**用户自填 LLM 配置**（新建研究 → LLM 配置）：接口地址 / API Key / 模型（默认 mimo-v2.6-pro），线程级透传，Key 脱敏展示。

## 三、信息架构（三区对话式工作台）

```
顶栏：品牌 · 当前主题切换 · 数据源徽章 · 真实/演示模式徽章 · 开发者模式开关
左栏：主题（一级对象，长期存活）+ 主题下研究线程
中栏：活动条（单行进度/上下文用量/异常数） + 对话流 + Canvas 报告 + 输入区
右栏：证据库（冲突/缺失置顶） + 记忆（候选需确认） + 产物版本（diff/回滚）
```

- **主题是一级对象**：证据库与记忆挂在主题下，跨线程可见、可复用（如「贵州茅台」下挂多次研究）；
- **对话流只允许 5 类消息**：用户气泡 / 助手回复 / 澄清反问卡 / 问题树提纲卡 / 异常决策卡（审批、冲突定主源）；系统事件（压缩/重试/降级）收进活动条，不刷屏；
- **Canvas 报告常驻**：主体为**连贯成文的研究正文**（导语+连续段落，行内 `[E?]` 引用点击跳转右栏证据高亮，推断句末标「（推断）」）；四分区明细（①事实清单 ②归纳与推断 ③待验证假设 ④数据质量说明）收进**默认折叠的「依据附录」**；选中任意文字弹「改这段 / 追问这个 / 查看证据」浮层；
- **输入区**：多行输入 + 模型选择器 + 「补充证据」（登记材料入库，与工具证据同权）；
- **开发者模式**（右上开关）：故障注入 / 手动压缩 / trace·token·成本 / 检查点恢复——trace 等调试信息**仅此模式可见**。

## 四、核心流程

```
说目标 → 合规预检(输入侧) → 目标充分性判断（规则 + LLM 槽位抽取，方案C）
       ├ 缺要素 → 确认式反问卡(≤2 问，动态引用目标原文，可跳过按默认) → 用户回答
       └ 充分 → 异步生成问题树(202 受理+后台执行+SSE 进度，规划+确定性校验+回炉≤2次) → 提纲卡（问题 1..N 连续编号）
用户决策：勾选/增删/上移下移改序/编辑问题，或直接说「去掉问题 2」「去掉估值部分」（删改后自动重排编号）
执行(按问题树 DAG)：取数 → 先落证据卡 → 活动条进度；失败重试1次→换源→降级不静默；审批门拦截
Canvas 出连贯正文报告 + 折叠附录（句句挂引用，经过确定性校验器）
修订：选中段落「改这段」/ 对话字段级指令 → 合规再过滤+引用校验 → vN（diff+变更说明，可回滚）
沉淀：候选记忆经确认写入主题；证据跨线程复用
```

**v4.1 体验改造**（详见 `docs/方案_澄清与提纲生成体验优化.md`）：LLM 槽位抽取消除误反问；全部异步按钮
「忙碌态三件套」（置灰+◌ 进行中+连点幂等）；/plan、/messages 异步化根治网关 504；问题树编号规范化
（UI 主显「问题 N」）；报告输出连贯成文、四分区收进折叠附录。

**问题树不是写死的**：内置 3 类研究剧本（风险梳理/多标的对比/事件归因）只提供问题域框架，LLM 依据目标动态实例化 3~8 个问题节点，每个节点必须声明 `sub_question`（子问题）与 `hypothesis`（假设）；目标/口径/标的变了，问题树随之改变。唯一预置轨迹的是演示模式（界面显式标注"非实时调用"）。

## 五、Harness 机制 → UI 映射（题目评分点对照）

| 机制 | 实现 | 呈现位置 |
|---|---|---|
| 输入侧合规拦截 | 荐股/买卖/预测/收益承诺/仓位 5 类正则拦截 | 发送时友好拒绝气泡 + 改写建议 |
| 问题树规划 + 前置校验 + 回炉 | 去重/必填参数/循环依赖/calc 入参/口径校验，错误喂回模型重生成（≤2 次） | 提纲卡（校验通过才展示） |
| 澄清反问 | 目标缺时间/范围/标的要素时先反问（≤2 问，可跳过） | 提纲之前的澄清卡 |
| 工具契约 | 名称/入参 schema/风险分级/超时/数据源标签 | 提纲节点工具徽章；dev 模式看完整契约 |
| 并行/重试/降级不静默 | 失败重试 1 次（指数退避）→ 换源 → 降级标注 | 活动条状态流 + 节点 ⚠ + 决策卡 |
| 检查点与恢复 | 每步落快照（计划状态/证据引用/成本），可从任意检查点恢复 | dev 模式检查点列表 |
| 上下文压缩 | 阈值**自动触发** + 证据白名单永不压缩 + 压缩后引用完整性校验（悬空回滚） | 活动条用量条 + "已压缩·引用完整"事件；手动入口仅 dev |
| 候选记忆（防污染） | Agent 只能写候选区，用户确认才入主题记忆 | 右栏记忆（确认/丢弃） |
| 审批门 | 外部动作/大批量拉取弹审批卡（风险等级/成本/数据量） | 对话流审批卡 |
| 停止规则 | 步数 12 / 成本 $0.5 / 时长 5min 触顶优雅收尾并明示原因 | 活动条明示 |
| 数据冲突状态机 | 双源数值+口径陈列 → 用户指定主源 → 记入数据质量说明 | 右栏冲突组置顶 + 决策卡 |
| 可观测性 | 逐步 trace/token/时延/成本记账 | 活动条（进度/成本）+ dev 全量 trace |
| 双模式显式区分 | 真实模式实时 LLM；演示模式轨迹重放 | 顶栏徽章 + 启动通知 + 线程「演示：」前缀 |
| 故障注入 | timeout/fail/missing/conflict/stale 五种 | 仅开发者模式 |
| 输出合规过滤 | 确定性正则改写 + 无引用推断强制标注 + 免责声明注入 | 报告分区 + 校验器 + 页脚声明 |

## 六、确定性校验器（报告可信的硬约束）

1. 事实区/概要每条 `refs` 必须非空且证据存在，**数值必须与证据对得上**；不满足强制移入「待验证假设」并标【移入待验证】；
2. 无引用推断强制加【未验证推断】前缀；推断必填置信度（高/中/低）与反驳条件（缺失自动补占位并预警）；
3. 页脚固定展示：数据来源、统计口径、生成时间、免责声明（"本报告为研究分析，不构成任何投资建议"）。

## 七、前端视图模型契约（治"丑/脏"）

> 所有列表/卡片/气泡只消费 `server/presenter.js` 产出的视图模型（title/summary/status/refs/badge/friendly_message）；
> 任何 `*_json`、payload、stack、trace 字段不得直接渲染；开发者模式为唯一例外。
> 回归测试断言：普通视图 API 响应不含裸 JSON 字段（见 tests/run-tests.mjs [9]）。

- 术语中文化：`degraded` → "这步没取到数据，已标记，不影响其他结论"；内部异常经 `friendlyError` 翻译；
- 测试脏串（如 "DSFSensf"）不允许进入普通视图：启动时自动归档历史脏线程（不物理删除）；演示线程统一「演示：」前缀；
- 视觉：浅色体系（白/浅灰+蓝紫主色）、圆角卡片、字阶 12/13/15；状态色 绿✓/黄⚠/灰○/蓝▶；**diff 用蓝（新增）/灰（删除），禁红绿**（避开红涨绿跌歧义）；实心主色按钮只留给「发送 / 开始研究」。

## 八、AI 的角色（人机边界）

| 环节 | LLM 负责 | 确定性代码负责 |
|---|---|---|
| 目标理解、问题树生成/修订 | ✓ | 目标充分性判断、问题树校验、依赖检查 |
| 选择工具、生成入参 | ✓（规划中固化） | schema 校验、风险分级、审批门、超时控制 |
| 归纳、压缩、报告合成/修订 | ✓ | **报告确定性校验器**、压缩白名单、引用完整性、diff 计算 |
| 合规 | 敏感表述自查 | **输入拦截、输出强制过滤、无引用推断强制标注、免责声明注入** |
| 记忆 | 提炼候选记忆 | **写入管控（用户确认才生效）** |

## 九、数据来源与诚实声明

- **双数据源可切换**：`DATA_PROVIDER=mock`（默认）为构造数据，证据卡显式标注 `mock`，仅演示机制；`DATA_PROVIDER=fuyao` 为**扶摇真实数据**，证据卡标 `real` 并携带 `endpoint + request_id` 双溯源字段（见 `docs/方案_接入扶摇真实数据源.md`）；
- **扶摇诚实降级**：真实取数失败按错误码决策——仅 network/timeout/2001/5xx 且开 `FUYAO_FALLBACK_MOCK` 才回退 mock（显式标注"非真实行情"）；3001/3002/3003/3004/2003/2004 **绝不回退**，诚实标注缺失（如 REST 无估值/公告端点、资讯库 2004 未开放外部、未上市主体检索为空），**数据缺失不编数、失败不静默**；
- 数据缺失/冲突/过期/失败**不静默生成"正常"结论**：降级通知 + 证据卡状态标注（missing/stale/conflict）+ 产物"数据质量说明"；
- 演示模式为预置轨迹重放，界面徽章 + 启动通知 + 线程名「演示：」三重显式声明。

## 十、已知边界（显式说明，不静默省略）

- **提纲改序用「上移/下移」按钮实现，未做拖拽手势**：按钮可达成任意顺序（反复交换即等价于拖拽），属体验增强项裁剪；
- **「改这段」局部改写通过带选中文本上下文的修订指令实现**（LLM 输出字段级 patch 生成 vN），非 DOM 级所见即所得编辑器；
- **iFinD MCP 未接入**（其授权依赖浏览器 Cookie 会话同步，无稳定服务端凭据）：`DATA_PROVIDER=ifind` 为接口留位；真实数据面由扶摇 API 承担（已接入），与题目"能力以实际可调用工具为准"一致；
- 构造数据集仅覆盖 5 个标的（000001.SZ/600519.SH/600309.SH/600036.SH/000300.SH）；
- 无依赖节点的并行取数为简化实现（顺序执行 + DAG 依赖标注）；
- 成本为估算值（展示用）；单机 SQLite（trace 展示保留最近 100 条）。

**未做（明确裁剪）**：多智能体协作、真实交易/持仓、多用户账号体系、移动端、LLM-as-Judge 评测报告。（真实数据源已接入扶摇，见 `docs/方案_接入扶摇真实数据源.md`）

## 十一、仓库结构

```
server/
  index.js       # Web 服务：REST + SSE + 静态前端（含主题/线程/问题树/修订 API）
  agent.js       # Harness 核心：澄清/问题树/执行/证据/校验器/修订/压缩/记忆/合规
  presenter.js   # 前端视图模型契约层（普通视图零 *_json）
  tools.js       # 工具注册表 + Mock/Fuyao Provider + 五种异常注入
  fuyao.js       # 扶摇真实数据 Provider（HTTP 客户端/降级映射/报告期推算）
  llm.js         # LLM 网关（OpenAI 兼容，含重试与 token 记账，线程级配置透传）
  db.js          # SQLite schema（topics/threads/messages/plans/steps/evidence/artifacts/memories/…）
  replays/demo-risk-scan.json  # 演示模式轨迹（对齐四分区报告 schema）
public/          # 三区对话式工作台前端（原生 JS，无构建步骤）
tests/
  run-tests.mjs  # 自动化测试 103 项（含视图模型契约 + 扶摇降级决策断言）
  fuyao-smoke.mjs # 扶摇真实数据源冒烟（真实网络，无 key 自动跳过）
  e2e-smoke.mjs  # 真实模式端到端冒烟脚本
docs/            # AI 使用与验证记录 / 测试说明 / 演示脚本 / 澄清与提纲体验优化方案（含 v4.1 实施记录）
```
